# CRM V1 开发执行计划（供 GLM 5.2 执行）

> 业务与技术基线：[CRM系统框架设计稿_简化版.md](CRM系统框架设计稿_简化版.md)、[业务实体.md](业务实体.md)、[CRM详细设计与反方评审.md](CRM详细设计与反方评审.md)。
>
> 本计划只交付客户经营基础闭环。执行者不得自行加入商机、立项、审批、合同、订单、回款、开票、项目等二期能力。

## 0. 执行总则

1. 以用户指定的 `whiteshader/ruoyi-react` 为基础，锁定一个 tag/commit 后记录在项目根目录 `README.md`；禁止直接依赖远程 `master`。
2. 不重写 RuoYi 的用户、部门、角色、菜单、认证体系。CRM 通过扩展表和服务层接入 `sys_user/sys_dept/sys_role/sys_user_role/sys_role_dept`。
3. 所有 CRM 表有 `tenant_id`、审计字段和 `version`；所有查询和写入从登录上下文取得租户，禁止相信请求体中的租户。
4. 所有写接口实现幂等键和乐观锁；所有关键写操作与领域审计、outbox 在一个数据库事务内。
5. 每完成一个任务：执行对应测试、运行格式检查、更新本计划中的状态，并提交一个聚焦的 Git commit。不要修改不相关文件或清除已有用户改动。
6. **本机只运行代码和测试客户端；MySQL、Redis、对象存储、文件扫描等状态服务不得部署或连接本机容器。**开发和测试统一连接远端测试宿主机 `zfh@192.168.2.37` 的 Docker 服务。
7. 远端测试环境的容器、网络、数据卷和 Compose 项目名称必须含 `test`。推荐前缀固定为 `crm-test-`；不得使用无环境后缀的通用名称，避免与后续环境混淆。
8. 钉钉 App ID、AgentId、Client ID、Client Secret、Corp ID、API Token 均属于部署密钥：仅放远端受限密钥文件或密钥服务，绝不写入代码、Markdown、`docker-compose.yml`、测试日志或 Git。

## 1. 目标、非目标与验收基线

### 1.1 V1 目标

`客户 → 主负责人/协同人 → 联系人/跟踪 → 提醒 → 状态流转 → 审计`

实现钉钉免登、组织同步和工作通知；PC 管理端与钉钉 H5 共用后端 API。

### 1.2 非目标

- 商机、报价、销售阶段、立项、钉钉审批。
- 合同、订单、出库、项目、验收、回款、开票。
- 客户外部联系人、客户群、营销自动化。

### 1.3 角色和数据范围（不可改写）

| 身份 | 可查看客户 | 可写内容 |
| --- | --- | --- |
| 销售/主负责人 | 自己创建 **或** 当前由自己主负责的客户 | 客户核心信息、协同人、联系人、跟踪、计划 |
| 协作销售 | 自己创建 **或** 当前分配给自己的协作客户 | 联系人、跟踪、附件；不能改核心信息、负责人、状态、计划 |
| 客户管理授权人员 | 其授予范围内客户 | 分配、移交、失效、归档、恢复 |
| 管理员 | 全部 | 全部及后台配置 |

客户重名规则：对同一租户的未归档客户，规范名称相同即拒绝创建；不提供重复创建申请或审核。

## 4. 必须自动化覆盖的 DoD

1. 同名未归档客户无法创建；归档后可以新建同名客户。
2. 两次并发移交同一客户，只有一次成功，任一时刻仅一名主负责人。
3. 普通销售仅可读取自己创建或当前成员关系中的客户；协作销售不能读取其他客户。
4. 协作销售能新增联系人、跟踪、附件，但不能改客户核心字段、状态、负责人和提醒计划。
5. 管理员可读取全部客户；客户管理授权人员只能在其 scope 范围内分配或移交。
6. 电话/微信跟踪未关联 `AVAILABLE` 图片即被拒绝；面谈可无附件。
7. 提交跟踪会替换旧计划；改期、暂停、失效、归档均正确取消未发送提醒。
8. 钉钉消息重试三次后进入最终失败；重放消费不产生第二条消息。
9. 恢复客户时下一次计划可选；未填不发送提醒、状态为待计划/不考核。
10. 跨租户以任意 ID 查询、更新、下载附件、导出均失败或不可见。
11. 所有关键写操作生成不可修改的审计事件；重复投影不重复生成客户动态。
